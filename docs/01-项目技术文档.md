| 项目   | 内容                                                                  |
| ---- | ------------------------------------------------------------------- |
| 项目名称 | CarAudioPlayer（车载风格在线音乐播放器）                                         |

## 一、产品功能

### 1.1 产品定位

一款面向车载场景的在线音乐播放器，采用深色车机主题（低亮度、高对比、大触控区），整体布局为「左侧一级导航 + 右侧内容区 + 底部常驻迷你播放条」，适配驾驶场景下的操作安全性与大屏可视性。

### 1.2 功能地图

```
CarAudioPlayer
├── 首页
│   ├── Banner 轮播（活动入口）
│   ├── 为你推荐歌单（横滑卡片）
│   ├── 热门榜单入口（前 4 个榜单）
│   └── 大家都在搜（热搜词横条）
├── 歌单广场
│   ├── 分类标签横条（全部/华语/欧美/日语/韩语等，选中态高亮）
│   └── 歌单卡片网格（4 列，封面 + 标题 + 播放量）
├── 排行榜
│   └── 全部榜单卡片列表（封面 + 前三首预览）
├── 搜索
│   ├── 热搜词（默认态）
│   ├── 输入联想（300ms 防抖，带封面）
│   └── 搜索结果页（歌曲列表，点击即播）
├── 播放（全局）
│   ├── 底部迷你播放条（封面/歌名/播放暂停/下一曲）
│   ├── 全屏播放页（封面/歌词双模式、进度条、收藏、队列面板）
│   └── 后台播放（前台服务 + 媒体通知）
└── 我的
    ├── 头像/昵称本地编辑
    ├── 我喜欢的歌曲（本地收藏）
    └── 收藏的歌单
```

### 1.3 功能设计取舍（有意为之的限制）

| 限制        | 原因                                           |
| --------- | -------------------------------------------- |
| 无账号体系     | 实习项目聚焦核心链路，收藏/头像全本地存储                        |
| VIP 歌曲不可播 | 播放地址依赖 QQ 音乐会员权益；UI 以金色 VIP 角标标识 + 自动跳转下一首兜底 |
| 语音搜索预留    | 车载语音需接入车机语音 SDK，属后续扩展点                       |
| 播放模式仅列表循环 | 随机/单曲属次要模式，预留入口                              |

## 二、技术框架

### 2.1 总体架构（双工程）

```
┌──────────────────────┐        HTTP         ┌───────────────────────┐        ┌──────────────┐
│   Android 客户端      │  ───────────────▶   │   Node 中转服务        │ ─────▶ │  QQ 音乐上游  │
│   (D:\AndroidProjects│   127.0.0.1:3200    │   (C:\Users\examp\    │        │  (手机端协议) │
│    \CarAudioPlayer)  │                     │    qq-music-api)      │        │              │
│                      │  ◀───────────────   │                       │ ◀───── │              │
│  Java + ViewBinding  │     JSON / 音频流    │  Koa2 + TypeScript    │        │              │
│  MVVM + LiveData     │                     │  tsx 直跑             │        │              │
└──────────────────────┘                     └───────────────────────┘        └──────────────┘
        │ 封面图直连 QQ 图床（公开无鉴权，不经过中转）
        └────────────────────────────────────────────────────────────────────▶ y.gtimg.cn
```

**为什么需要中转服务**：QQ 音乐的播放地址（vkey）是带登录态的动态签名，App 无法本地计算；中转服务统一持有 Cookie、处理签名与风控，对外暴露干净的 HTTP 接口。

### 2.2 客户端技术选型

| 技术点  | 选型                                      | 理由                                              |
| ---- | --------------------------------------- | ----------------------------------------------- |
| 语言   | Java                                    | 团队存量项目为 Java，保持一致                               |
| 视图绑定 | ViewBinding                             | 官方推荐，替代 findViewById，类型安全                       |
| 架构   | MVVM（ViewModel + LiveData）              | UI 与数据分离；LiveData 感知生命周期，从结构上避免回调操作已销毁视图导致的 NPE |
| 网络   | 手写 HttpURLConnection + 线程池              | 无第三方依赖；封面与 JSON 请求量级小，可控可讲                      |
| 图片加载 | 自研 ImageLoader                          | LruCache + 磁盘缓存 + 降采样，替代 Glide，深化缓存原理理解         |
| 播放   | Media3（ExoPlayer + MediaSessionService） | 工业级播放引擎；后台播放 + 系统媒体控制，契合车机场景                    |
| 本地存储 | Room + SharedPreferences + 文件           | 收藏用 Room（结构化 + 可观察）；昵称用 SP；头像用私有文件              |
| 列表   | RecyclerView + ListAdapter/DiffUtil     | 局部刷新，避免全量重绑                                     |

### 2.3 客户端分层架构

```
┌────────────────────────────────────────────────────────────┐
│ UI 层（ui/）                                                │
│   MainActivity：侧栏导航 + Fragment 栈 + 迷你播放条          │
│   13 个 Fragment：首页/歌单广场/榜单/搜索/搜索结果/           │
│   榜单详情/歌单详情/专辑详情/歌手详情/播放页/我的/队列面板      │
│   规则：只画界面、发导航意图；网络回调只订阅 LiveData          │
├────────────────────────────────────────────────────────────┤
│ ViewModel 层（ui/*/XxxViewModel.java）                      │
│   职责：持有页面状态（LiveData）、编排数据请求                │
│   规则：回调只 setValue，绝不触碰 View/binding               │
├────────────────────────────────────────────────────────────┤
│ 数据层                                                      │
│   data/remote/QQMusicApi.java   网络请求 + ApiCache 缓存     │
│   data/repository/              收藏仓库（异步）、缓存、资料  │
│   player/PlaybackManager        播放单例（队列/切歌/状态）    │
│   player/ImageLoader            图片加载（内存+磁盘+降采样）  │
│   data/local/                   Room 数据库（收藏两张表）     │
├────────────────────────────────────────────────────────────┤
│ 播放引擎（service/PlaybackService）                          │
│   MediaSessionService + ExoPlayer + AudioFocusHelper        │
└────────────────────────────────────────────────────────────┘
```

### 2.4 中转服务架构

```
src/
├── app.ts / koaApp.ts / server.ts     入口、Koa 装配、HTTP 服务（端口 3200）
├── routes/
│   ├── router.ts                      按 api-metadata.ts 自动注册路由
│   └── api-metadata.ts                接口元数据（路径、参数、示例）
├── controllers/                       每接口一个控制器（getRanks.ts 等 40+ 个）
├── services/apis/                     上游请求封装（UCommon 统一签名出口）
└── config/user-info.ts                Cookie 持久化（config/user-info.json）
```

关键设计：

- **控制器-服务分离**：控制器只做参数解析与响应包装，上游请求统一走 `services/apis/UCommon`
- **路由元数据驱动**：新增接口只需在 api-metadata.ts 加一条记录，路由自动注册
- **本项目对中转的定制改动**：
  - `getRanks.ts`：mid 解析 worker 池并发 15 + `songId→songmid` 永久映射缓存（midCache）
  - `getSongInfo.ts`：`song_id` 参数转数字（修复类型导致的解析失败，详见 Bug 报告）

## 三、UI 实现流程

### 3.1 整体 UI 结构

采用「侧栏 + 内容区 + 迷你条」的车机三段式布局：

```
┌──────┬───────────────────────────────────────────┐
│      │  一级页面（add/hide 驻留，保状态）           │
│ 侧栏  ├───────────────────────────────────────────┤
│ 导航  │  二级页面（addToBackStack 压栈）            │
│      │  榜单/歌单/专辑/歌手/搜索结果/播放页/我的     │
│      ├───────────────────────────────────────────┤
│      │  迷你播放条（全局常驻）                      │
└──────┴───────────────────────────────────────────┘
```

- 一级 Tab（首页/歌单/榜单/搜索）用 `add/hide` 驻留，切换不丢状态
- 二级页面压入返回栈，返回不销毁一级页面
- 迷你条全局唯一，观察 `PlaybackManager.state()` 这一个 LiveData

### 3.2 单个页面的标准实现流程（以歌单广场为例）

```
① 布局 XML（fragment_songlist_square.xml）
   分类 RecyclerView（横向 LinearLayoutManager）+ 歌单网格（GridLayoutManager 4 列）

② ViewModel（SongListSquareViewModel）
   持有 3 个 LiveData：categories / playlists / hint
   loadCategories() / loadPlaylists(categoryId, sortId, page) 内部调 QQMusicApi
   网络回调只 setValue，不碰任何 View

③ Fragment（SongListSquareFragment）
   onViewCreated：
     - 初始化两个 RecyclerView + Adapter
     - observe(getViewLifecycleOwner(), ...) 订阅三个 LiveData
     - 分类点击：currentCategoryId 更新 + setSelected(position) 移动选中态 + loadPlaylists()
     - viewModel.loadCategories() + viewModel.loadPlaylists(默认分类)

④ Adapter（ChipAdapter / PlaylistAdapter）
   ChipAdapter：setSelected() 驱动选中背景切换（bg_chip_selected）
   PlaylistAdapter：封面走 ImageLoader，点击回调 openSongListDetail
```

### 3.3 关键 UI 技术点

| 技术点           | 实现                                                                                |
| ------------- | --------------------------------------------------------------------------------- |
| ViewBinding   | 每个布局生成 `XxxBinding`，`onDestroyView` 置 null 防泄漏                                    |
| 骨架屏           | 首页 `home_skeleton`（灰色占位块）与 `home_content` 切换，首次数据到达或失败时 `showContentOnce()` 一次性切换 |
| 头像圆形裁剪        | `ImageLoader.toCircle(Bitmap)`：BitmapShader + 居中裁剪矩阵，抗锯齿                          |
| VIP 角标        | 歌名行右侧 TextView，`SongAdapter` 按 `song.payPlay` 显隐                                  |
| DiffUtil 局部刷新 | `SongAdapter extends ListAdapter`，`areItemsTheSame/areContentsTheSame` 双判         |
| 深色车机主题        | `bg_main #0E1116` 深底 / 品牌绿 `#31C27C` / 大触控区（tab 高 56dp+）                          |

## 四、网络请求流程

### 4.1 网络分层

```
Fragment（点击/进入页面）
   └─▶ ViewModel.loadXxx()
          └─▶ QQMusicApi.xxx(args, Callback)
                 ├─ run(() -> ...)              固定 4 并发线程池
                 ├─ httpGetJsonCached(path, key)  先查 ApiCache
                 │     ├─ 命中未过期 → 直接解析返回（0ms）
                 │     └─ 未命中 → httpGet → parseBody 剥壳 → ApiCache.put 回填
                 ├─ 失败兜底：getStale(key) 过期数据，网络异常时仍可展示
                 └─ post/postError                回调切回主线程
                        └─▶ Callback.onSuccess → LiveData.setValue
                                              └─▶ Fragment observer 更新 UI
```

### 4.2 接口契约（本项目实际使用的 18 个）

| 分类  | 接口                                         | 用途                                 |
| --- | ------------------------------------------ | ---------------------------------- |
| 榜单  | `GET /getRanks?topId&limit`                | 榜内歌曲（客户端不带 resolveMid，详见 Bug 报告 1） |
| 榜单  | `GET /getTopLists`                         | 全部榜单卡片                             |
| 歌曲  | `GET /getSongInfo?songid`                  | songId→mid 解析（播放前按需调用）             |
| 歌曲  | `GET /getMusicPlay?songmid`                | 播放地址（含 vkey）                       |
| 歌曲  | `GET /getLyric?songmid`                    | LRC 歌词                             |
| 搜索  | `GET /getSearchByKey?key`                  | 关键词搜索 + 输入联想                       |
| 搜索  | `GET /getHotkey`                           | 热搜词                                |
| 歌单  | `GET /getSongLists?categoryId&sortId&page` | 歌单广场列表                             |
| 歌单  | `GET /getSongListCategories`               | 歌单分类                               |
| 歌单  | `GET /getSongListDetail?disstid`           | 歌单详情                               |
| 推荐  | `GET /getRecommend`                        | 首页推荐（歌单+榜单聚合）                      |
| 推荐  | `GET /getRecommendBanner`                  | 首页轮播                               |
| 歌手  | `GET /getSingerHotsong?singermid`          | 歌手热门歌曲                             |
| 歌手  | `GET /getSingerAlbum?singermid`            | 歌手专辑                               |
| 歌手  | `GET /getSingerDesc?singermid`             | 歌手介绍                               |
| 专辑  | `GET /getAlbumInfo?albummid`               | 专辑信息                               |
| 专辑  | `GET /getAlbumSongs?albummid`              | 专辑歌曲                               |

响应统一结构 `{response: {...}}`，客户端 `parseBody()` 剥壳 + 字段多 key 兼容（`songmid/mid/song_mid` 等）。

### 4.3 两种 URL 的本质区别

| 类型           | 获取方式                      | 是否过期            |
| ------------ | ------------------------- | --------------- |
| **封面图 URL**  | 客户端本地拼接：图床域名 + albumMid   | 永久公开，无鉴权        |
| **播放地址 URL** | 必须请求 `getMusicPlay`，服务端返回 | 含 vkey 动态签名，会过期 |

### 4.4 网络健壮性设计

- **超时**：连接/读取均 8s
- **错误分类**：`SocketTimeoutException`（服务超时）/ `ConnectException`（服务未启动）/ `IllegalStateException`（接口返回错误）分别转成用户可读文案
- **失败兜底**：网络失败时 `ApiCache.getStale()` 返回过期旧数据，页面不白屏
- **播放失败**：取地址失败自动跳下一首（`consecutiveFailures` 计数防止整队列失败时无限跳）

## 五、数据存储流程

### 5.1 存储选型总览

| 数据       | 存储方式                                             | 位置     | 生命周期                 |
| -------- | ------------------------------------------------ | ------ | -------------------- |
| 收藏的歌曲/歌单 | Room（favorite_song / favorite_playlist）          | SQLite | 永久（用户删除才清）           |
| 头像       | 私有文件 `filesDir/avatar.jpg`（512px JPEG）           | 内部存储   | 永久                   |
| 昵称       | SharedPreferences（user_profile）                  | XML    | 永久                   |
| 接口数据缓存   | ApiCache：内存 Map + 磁盘文件（cacheDir/api_cache/）      | 缓存目录   | TTL 分级（10min~24h）    |
| 封面图片     | ImageLoader：LruCache + 磁盘（cacheDir/image_cache/） | 缓存目录   | 内存随进程；磁盘 50MB 上限 LRU |
| 播放队列     | 内存 List\<OnlineSong\>                            | 进程内存   | 进程存活                 |

### 5.2 Room 数据库设计

```sql
favorite_song（主键 songMid）
  ├── name / singer / singerMid / album / albumMid / interval
  └── favoriteTime（收藏时间，排序用）

favorite_playlist（主键 disstid）
  ├── name / cover
  └── favoriteTime
```

- 版本 v3，v2→v3 迁移 `DROP TABLE song`（废弃的铃声曲库表），收藏数据无损
- **禁止主线程查询**：`allowMainThreadQueries` 已移除，`FavoritesRepository` 全部 API 为异步回调式（后台单线程池 + 主线程回抛）
- 收藏列表用 `LiveData` 观察（Room 自动后台计算并驱动 UI 刷新）

### 5.3 ApiCache 两级缓存（自研）

```
读：内存 ConcurrentHashMap 命中？ → 返回
    磁盘文件命中且未超 TTL？ → 读文件 + 回填内存 → 返回
    都没有 → 返回 null（调用方走网络，成功后 put 双写回填）

TTL 分级：
    搜索类（联想/结果）   10 分钟
    榜单/歌单/歌手热歌等  1 小时
    分类/歌词/mid/专辑信息/歌手介绍  24 小时

写：put(key, json) → 内存 + 磁盘文件双写（磁盘写失败不影响内存）
```

### 5.4 收藏功能完整链路

```
用户点收藏（播放页红心 / 列表心形 / 歌单收藏按钮）
  → FavoritesRepository.toggleSongFavorite(song, callback)
      → 后台线程：dao 判断存在性 → insert / delete
      → Room 自动触发 observeFavoriteSongs() 的 LiveData 刷新
          → MineFragment observer：重建列表 + setFavoriteMids 批量注入收藏态
      → 主线程回调：更新按钮图标 + Toast
```

## 六、核心链路串联（全流程走查）

以「用户搜索 → 点歌 → 播放 → 收藏」为例，串联全部技术点：

```
① 搜索输入（SearchFragment）
   EditText 输入 → 300ms 防抖 → SearchInputViewModel.loadSuggest(key)
   → QQMusicApi.searchSongs → ApiCache(10min) 或网络 → searchByKey
   → LiveData 推送 → 联想列表（SongAdapter，封面走 ImageLoader 三级读）

② 点击歌曲（SongAdapter → PlaybackManager.playQueue）
   → playAt(song)：
       ├─ 已有 playUrl？直接播（0ms）
       ├─ mid 为空（榜单快路径）？→ resolveMid(songId) → ApiCache(24h) 或网络
       └─ getPlayUrl(mid) → 网络取 vkey 地址
   → controller.setMediaItem → PlaybackService.ExoPlayer 出声
   → state() LiveData 推送 → 迷你条/播放页同步封面、歌名、进度

③ 播放页（PlayerFragment）
   observe state()：切歌 → onSongChanged → 封面加载 + loadLyric
   → PlayerViewModel → ApiCache(24h) 或网络 → LyricParser 解析 LRC
   → 进度推进 → updateLyric 高亮当前行

④ 收藏（PlayerFragment 红心）
   → FavoritesRepository.toggleSongFavorite（异步写 Room）
   → Room LiveData 自动刷新「我的」页列表
```

## 七、性能优化（提前实施，详见专项文档）

| 层面  | 措施                            | 效果（实测）              |
| --- | ----------------------------- | ------------------- |
| 服务端 | mid 映射永久缓存 + 并发 15            | 热歌榜解析 28.4s → 0.14s |
| 客户端 | 榜单两段式（列表不带 mid，播放按需解析）        | 打开榜单必超时 → 0.2s 秒开   |
| 缓存  | ApiCache 内存+磁盘两级 + TTL 分级     | 二次进任何页面约 0ms        |
| 图片  | LruCache + 磁盘 + 降采样 + 裁圆      | 封面二次 0ms，实测 616 张落盘 |
| 渲染  | DiffUtil 局部刷新 + 骨架屏 + 去过绘     | 刷新不闪、首屏有占位          |
| 主线程 | 禁 Room 主线程查询 + 全异步仓库 + IO 后台化 | 主线程零阻塞 IO           |
| 架构  | MVVM 重构 10 个 Fragment         | 结构上消除回调 NPE*        |
