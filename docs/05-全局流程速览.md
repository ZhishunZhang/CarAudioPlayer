# CarAudioPlayer 全局流程速览

> 用途：先过这 6 条"全局线"建立整体认知；想抠细节时，按每条末尾的"关键位置"去翻源码。
> 配合 `04-源码阅读清单.md` 使用：阅读清单管"看什么文件"，本文档管"流程怎么走"。
>
> 阅读方式约定：**"点"要详细展开（代码/机制/边界），"线"用一句话流程串起来（每步做什么、谁在动、结果是什么）。**

## ① 列表数据加载（歌单广场/榜单/搜索等一切列表）

点击/进页 → ViewModel 调 `QQMusicApi.xxx`，任务扔进线程池（EXECUTOR），主线程立即返回 → 后台先查 ApiCache（内存命中秒回 / 磁盘命中读文件回填内存 / 全 miss 则单飞合并发网络）→ 拿到 JSON 剥壳（parseBody 剥 `{response}`、peel 剥 data 壳）解析成模型对象，顺带拿到各自的"钥匙"（mid/disstid/topId）→ 网络失败则 getStale 拿过期缓存兜底（页面不白屏）→ post 回主线程 → LiveData setValue → observer 触发 → Adapter 刷新 UI。

- 关键位置：`QQMusicApi.httpGetJsonCached`（缓存+单飞）、`ApiCache.get`、`QQMusicApi.parseBody/peel/parseSong`、`SongListSquareViewModel.loadPlaylists`、`SongListSquareFragment` 的 observer
- 缓存 TTL 三档：搜索 10 分钟 / 榜单歌单 1 小时 / 分类歌词 24 小时

## ② 播放

数据接口返回 JSON，解析时顺带拿到 mid（榜单例外，先用 songId 调 getSongInfo 换 mid）→ mid 拼进 `/getMusicPlay?songmid=xxx`，经 USB 隧道中转至 QQ 音乐服务器 → 服务器校验 Cookie（身份）和权限后签发播放地址（CDN 域名 + 文件名含 mid + vkey 临时通行证）→ 响应原路返回，App 取出 URL 交给 ExoPlayer（同时乐观切换：歌名/封面立即上屏，不等网络）→ ExoPlayer 拿 URL 去 CDN 取回音频压缩字节，解码成 PCM，写入音频输出，出声。

- 关键位置：`PlaybackManager.playAt`（乐观切换）→ `QQMusicApi.getPlayUrl`（不缓存，vkey 会过期）→ `PlaybackManager.playPrepared`（setMediaItem/play + 状态广播）→ `PlayerFragment.onSongChanged`
- 凭证接力：mid 定位（永久）→ Cookie 验身份（中转持有）→ vkey 授权（每次现签，几分钟有效）

## ③ 图片加载（封面/头像/Banner 一切图）

Adapter 绑定行 → `ImageLoader.load`：同步设占位图 + 打 tag（防列表复用错位）→ 内存 LruCache 命中直接显示（无动画）→ 未命中则进后台线程：磁盘命中读字节 / 全 miss 则下载（QQ 图床直连，不走中转）并写盘（超 50MB 按时间删除）→ 降采样解码（先 inJustDecodeBounds 读尺寸，再按 2 的幂采样率解像素，防 OOM）→ 回填内存 LruCache → 回主线程 tag 校验通过后 setImageBitmap + 200ms 淡入。

- 关键位置：`ImageLoader.load`、`readFromDiskOrNetwork`、`decodeSampled`、`trimDiskCache`
- 封面两种形态：完整 URL（歌单/榜单/Banner 接口直给）vs MID 本地拼（歌曲/专辑，`coverUrl(albumMid)`）

## ④ 收藏（红心/收藏歌单）

点红心 → FavoritesRepository 后台单线程池查存在性 → insert 或 delete（REPLACE 策略，主键冲突整行覆盖，重复收藏幂等）→ Room 自动检测表变化，LiveData 重发最新列表 → "我的"页 observer 自动收到并刷新列表（零手动刷新代码）→ 结果回主线程，图标切换 + Toast。

- 关键位置：`FavoritesRepository.toggleSongFavorite`、`FavoritesDao`（@Insert REPLACE / LiveData 查询）、`MineFragment` 的 observer
- 内存模型与持久模型分离：OnlineSong（不入库）↔ FavoriteSong（Room 实体，字段拷贝互转）

## ⑤ 歌词

换歌（song 流触发）→ 先上"歌词加载中…"占位 → `lyric(mid)` 请求（24h 缓存）→ 拿到 LRC 文本 → LyricParser 正则提取时间戳、升序排列成 LyricLine 列表 → 回主线程提交给 LyricAdapter → 播放中每 500ms（progress 流）拿当前进度调用 findLineIndex 找出当前行 → 高亮 + 平滑滚动居中；用户拖动歌词则进入浏览态（暂停自动跟随），停手 6 秒且正在播放才滚回播放行，拖动后点某行则 seek 到该句。

- 关键位置：`QQMusicApi.lyric`、`LyricParser.parse/findLineIndex`、`PlayerFragment.updateLyric/scrollToLyricLine`、`LyricLine.emptyFallback`（无歌词占位）

## ⑥ 页面导航（Tab / 压栈 / 返回）

点 Tab → 已有则 hide 旧的 show 新的（add/hide 驻留，Fragment 不销毁、ViewModel 不丢，切回秒回状态）；没有则 add → 点卡片进详情 → `push`：add 叠加 + addToBackStack 记入返回栈（下面的页面不销毁，只是被盖住，根布局 clickable 防点击穿透）→ 按返回键：先收全屏播放页覆盖层（播放不中断），再逐层弹栈（弹出的那层销毁，下面的重见天日）→ 弹无可弹才 finish 退出 App。

- 关键位置：`MainActivity.showTab`（驻留）/ `push`（压栈）/ `goBack`（返回）/ `popDetails`（切 Tab 时整摞清空二级栈）
- 播放页覆盖层：不进返回栈，从播放条位置 scaleY 长出（280ms），返回/下滑收起

## 附：横跨所有流程的 5 条通用规律

1. **网络传输永远是字节**：文本接口 readLine → String；图片接口 toByteArray → byte[]。"读成字符串"还是"原样收字节"是两条路的分叉点。
2. **解析两次**：String → JSONObject（通用容器，用 opt 多 key 消化脏字段）→ 模型对象（强类型，下游只见干净字段）。
3. **回调必回主线程**：所有异步完成后 MAIN.post 回主线程，配合 LiveData 只能主线程 setValue 的约束。
4. **先占位再替换**（乐观/渐进）：界面立即有东西（占位图/加载中/本地已有信息），异步数据回来后替换——点歌秒开播放页、图片淡入都是这个模式。
5. **缓存做在正确的层**：ApiCache 存原始 body（解析逻辑升级后老缓存可用）；播放地址不缓存（vkey 会过期），改为回填 song.playUrl 走内存快速路径。
